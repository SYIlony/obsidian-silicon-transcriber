# 全局阶段写入方案

## 一、当前机制分析

### 1.1 笔记物理结构

```
> [!info] [[视频.mp4]] (时长)           ← info头部（固定）
>   🧩 视频已拆分为 N 个部分

%%BATCH_0_START%%                        ← 锚点0
#### ⏱️ 00:03 知识点1  🎬 [[...]]
- key_points...
%%BATCH_0_END%%

%%BATCH_1_START%%                        ← 锚点1
#### ⏱️ 05:30 知识点2  🎬 [[...]]
- key_points...
%%BATCH_1_END%%

## 考试核心总览                          ← META头部（全局后插入）
...

## 老师强调的注意点                      ← META尾部（全局后追加）
...

## 例题与方法
...
```

### 1.2 当前两套写入机制

| 机制 | 函数 | 原理 |
|------|------|------|
| 锚点替换 | `safeEditorReplace` | 定位 `%%BATCH_N_START%%` / `%%BATCH_N_END%%`，替换中间内容 |
| 全量追加 | `vault.modify` | 读取全文，拼接新内容，写回 |

### 1.3 当前全局阶段的问题

当前 `runGlobalCorrectionAnalysis` 做的是**全量重建**：
1. 收到 LLM 返回的 topics
2. 按时间戳分配到各批次锚点
3. 重新收集 ASR 原文
4. 逐个用 `safeEditorReplace` 完全重写每个锚点

问题：
- 没改的知识点也被重写（浪费）
- 原文重新收集逻辑复杂且容易出错
- topic 跨批次时分配逻辑复杂

## 二、新方案：按需替换 + 头尾追加

### 2.1 核心思路

全局阶段分三步，每步用不同的写入策略：

| 步骤 | 做什么 | 写入方式 | 为什么 |
|------|--------|---------|--------|
| ① 差异替换 | 只替换有变化的锚点内容 | `safeEditorReplace`（逐块） | 没变化的块不碰，避免破坏 |
| ② 头部插入 | 在锚点区域之前插入考试核心总览 | `editor.replaceRange` 在头部锚点前插入 | 一次性插入，简单高效 |
| ③ 尾部追加 | 在锚点区域之后追加老师强调+例题方法 | `vault.modify` 追加 | 只加不改，零风险 |

### 2.2 步骤①：差异替换

**哪些情况需要替换锚点内容**：

| 情况 | 处理 |
|------|------|
| LLM 对某个知识点做了合并/拆分，导致锚点内的内容结构变了 | 替换该锚点 |
| LLM 调整了标题或 key_points 内容 | 替换该锚点 |
| 某个锚点的内容完全没变（LLM 原样保留） | **跳过，不替换** |

**实现方式**：

```typescript
// 全局校验返回的 topics 列表
const result = await getGlobalCorrectionSummary(preliminarySummaries);
const topics = result.chapters;
const metaData = result.metaData;

// 按时间戳分配 topics 到各批次锚点
// （复用现有的分配逻辑，但去掉 matchedRaw 收集）

for (let i = 0; i < jobs.length; i++) {
    const job = jobs[i];
    const anchorId = job.anchorId;
    
    // 构建 this batch 的最终内容
    let finalContent = "";
    // ... 分配 topics 到此 batch，构建 finalContent ...
    
    // 读取当前锚点内容
    const docContent = editor.getValue();
    const startMarker = `%%${anchorId}_START%%`;
    const endMarker = `%%${anchorId}_END%%`;
    const startIndex = docContent.indexOf(startMarker);
    const endIndex = docContent.indexOf(endMarker);
    
    if (startIndex !== -1 && endIndex !== -1) {
        const currentContent = docContent.substring(
            startIndex + startMarker.length, 
            endIndex
        ).trim();
        
        // 差异检测：如果内容没变，跳过
        if (currentContent === finalContent.trim()) {
            console.log(`[全局] 批次 ${i} 内容无变化，跳过`);
            continue;
        }
        
        // 内容有变化，执行替换
        await this.safeEditorReplace(editor, anchorId, finalContent, i + 1, notice);
    }
}
```

**优化点**：大部分情况下，阶段1已经整理好了，全局阶段只是微调标题或偶尔合并/拆分。大部分锚点内容不会变，差异检测可以跳过大量不必要的写入。

### 2.3 步骤②：头部插入

考试核心总览需要插入在 info 头部之后、第一个锚点之前。

**实现方式**：

```typescript
// 构建 META 头部内容
const metaHeader = `## 考试核心总览\n\n${metaData.exam_focus}\n\n`;

// 在第一个锚点之前插入
const docContent = editor.getValue();
const firstAnchor = "%%BATCH_0_START%%";
const insertPos = docContent.indexOf(firstAnchor);
if (insertPos !== -1) {
    const insertPosEditor = editor.offsetToPos(insertPos);
    editor.replaceRange(metaHeader, insertPosEditor, insertPosEditor);
}
```

**特点**：一次性插入，不碰任何锚点内容，零风险。

### 2.4 步骤③：尾部追加

老师强调注意点和例题方法追加在最后一个锚点之后。

**实现方式**：

```typescript
// 构建 META 尾部内容
let metaFooter = '';
if (metaData.emphasis.length > 0) {
    metaFooter += `## 老师强调的注意点\n\n`;
    metaData.emphasis.forEach(e => metaFooter += `- ${e}\n`);
    metaFooter += '\n';
}
if (metaData.examples.length > 0) {
    metaFooter += `## 例题与方法\n\n`;
    metaData.examples.forEach(ex => {
        metaFooter += `#### ⏱️ ${ex.timestamp} ${ex.topic}  🎬 [[${fileName}#t=${ex.timestamp}|${ex.timestamp}]]\n`;
        metaFooter += `- 方法：${ex.method}\n\n`;
    });
}

// 在最后一个锚点之后追加
const docContent = editor.getValue();
const lastBatchNum = totalChunks - 1;
const lastEndMarker = `%%BATCH_${lastBatchNum}_END%%`;
const appendPos = docContent.indexOf(lastEndMarker);
if (appendPos !== -1) {
    const insertPos = editor.offsetToPos(appendPos + lastEndMarker.length);
    editor.replaceRange('\n\n' + metaFooter, insertPos, insertPos);
}
```

**特点**：只追加不修改，零风险。

### 2.5 整体流程

```
全局阶段开始
  │
  ├── 1. 调用 LLM 获取 GlobalCorrectionResult（chapters + metaData）
  │
  ├── 2. 差异替换：逐个锚点检测，只替换有变化的
  │     ├── 批次0：内容变了？→ 替换 / 没变？→ 跳过
  │     ├── 批次1：内容变了？→ 替换 / 没变？→ 跳过
  │     └── ...
  │
  ├── 3. 头部插入：在锚点区域之前插入"考试核心总览"
  │
  └── 4. 尾部追加：在锚点区域之后追加"老师强调"+"例题方法"
```

### 2.6 为什么不用全量重建？

| | 全量重建（当前） | 按需替换（新方案） |
|---|---|---|
| 写入次数 | 每个锚点都写 | 只写有变化的锚点 |
| 风险 | 高（全部重写，容易出错） | 低（没变的不碰） |
| 速度 | 慢（全量写入+验证） | 快（大部分跳过） |
| 原文依赖 | 需要重新收集ASR原文 | 不需要（去掉原文了） |
| 跨批次处理 | 复杂（topic跨批次分配） | 简单（按时间戳分配，内容差异检测） |

### 2.7 关于"按时间戳分配 topics 到锚点"的简化

当前 `runGlobalCorrectionAnalysis` 有复杂的 topic-to-batch 分配逻辑。新方案可以简化：

由于阶段1已经把每个块整理好了，全局阶段返回的 topics 大部分和阶段1的输出一致（只是标题微调或偶尔合并/拆分）。

**简化策略**：全局阶段的 topics 按 timestamp 排序后，直接按时间范围分配到对应的锚点。不需要精确匹配——如果某个 topic 的时间戳落在某个批次的时间范围内，就放到那个锚点里。

```typescript
// 简化版分配逻辑
for (let i = 0; i < jobs.length; i++) {
    const job = jobs[i];
    const jobStart = job.segments[0]?.start ?? 0;
    const jobEnd = i < jobs.length - 1 
        ? (jobs[i + 1].segments[0]?.start ?? totalDuration)
        : totalDuration;
    
    // 找出属于这个批次的 topics
    const batchTopics = topics.filter(t => {
        const tSec = parseTime(t.timestamp);
        return tSec >= jobStart - 5 && tSec < jobEnd;
    });
    
    // 构建 this batch 的最终内容
    let finalContent = "";
    for (const topic of batchTopics) {
        finalContent += `#### ⏱️ ${topic.timestamp} ${topic.title}  🎬 [[${fileName}#t=${topic.timestamp}|${topic.timestamp}]]\n`;
        if (topic.key_points) {
            topic.key_points.forEach(kp => finalContent += `- ${kp}\n`);
        } else if (topic.summary) {
            finalContent += `${topic.summary}\n`;
        }
        finalContent += `\n`;
    }
    
    // 差异检测 + 替换（见上文）
}
```

## 三、总结

| 写入场景 | 策略 | 风险 | 效率 |
|---------|------|------|------|
| 锚点内容有变化 | `safeEditorReplace` 替换 | 低（有重试+验证） | 高（只写有变化的） |
| 锚点内容无变化 | 跳过 | 零 | 最高（不写） |
| 考试核心总览 | 头部插入（锚点之前） | 零（只插入不改已有内容） | 高（一次操作） |
| 老师强调+例题方法 | 尾部追加（锚点之后） | 零（只追加不改已有内容） | 高（一次操作） |
